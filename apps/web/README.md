# Проходная: экраны

Next.js, TypeScript, Tailwind. Четыре маршрута ходят в API и Keycloak (realm `prohodnaya`, клиент `web`). `/gate` и `/phone` используют PKCE; остальные экраны сохраняют существующий password grant стенда.

| Маршрут | Учётка стенда | Что делает |
| --- | --- | --- |
| `/gate` | `gate` | вход/выход, QR попытки, кадр КПП, `POST /attempts/:id/decide` |
| `/phone` | `worker` | ключ ECDSA P-256, скан QR, собственная смена, GPS и симуляция зоны |
| `/admin` | `admin` | карточка и эталон, список, журнал |
| `/manager` | `manager` | кто внутри и с какого времени |

Пароль учёток стенда — `dev-only`. Адреса по умолчанию: API `http://localhost:3001`, Keycloak `http://localhost:8081`. Переопределение на сборке: `NEXT_PUBLIC_API_URL` и `NEXT_PUBLIC_KEYCLOAK_URL`.

```bash
cd apps/web
npm ci
npm run dev
```

Локальный `npm run dev` открывается на `http://localhost:43123`. Телефон и ноутбук на стенде открывают один адрес `https://<LAN_IP>:8443`. Как поставить сертификат на Android — в [docs/run.md](../../docs/run.md). Публичный туннель для этого не нужен.

## Проходная и телефон Дениса

На `/gate` и `/phone` вход через Authorization Code + PKCE S256; кадровые и управленческие экраны сохраняют свой существующий вход. Общий API-клиент команды сохранён в `src/lib/api.ts`; клиент двух экранов — `src/lib/pass-api.ts`.

### Реализация двух экранов

Next.js App Router + React + TypeScript. Node.js 22.18 или новее (проверено на Node 24). Стили — обычный CSS, без второго UI-kit и внешних шрифтов.

## Запуск

```sh
cd apps/web
npm ci
cp -n .env.example .env.local
npm run dev -- --port 3002
```

Для отдельной проверки PKCE открыть `http://localhost:3002/gate` или `/phone`: этот порт разрешён в realm из репозитория. Общий стенд для телефона — `https://<LAN_IP>:8443`, один origin на ноутбуке и телефоне. Настройка — в [docs/run.md](../../docs/run.md). Cloudflare и localhost.run не нужны.

В `.env.local` задать публичные адреса API и Keycloak из `.env.example`; секретов и client secret у браузерного клиента нет. После изменения NEXT_PUBLIC-переменных перезапустить dev или пересобрать production. На телефоне `localhost` обозначает сам телефон. Камере, WebCrypto и PKCE нужен безопасный контекст: на стенде это `https://<LAN_IP>:8443`.

## Реализовано

- Вход/выход Keycloak через Authorization Code + PKCE S256, контроль роли для действий. Access/refresh tokens хранятся адаптером в памяти; token обновляется перед API-запросом. Постоянной проверки iframe нет. Сервер независимо проверяет JWT и роль.
- `/gate`: `POST /attempts`, реальный QR со ссылкой на `/phone` и fragment с attempt/nonce, показ серверного срока без автообновления QR. Отмена только кнопкой «Закрыть QR». Скрытие вкладки попытку не отменяет. При потере сети отмена не гарантируется: действует TTL backend (25 секунд).
- Камера КПП: JPEG-снимок или загрузка JPEG/PNG до 5 MiB с уменьшением до 1024 px, остановка камеры после снимка, отдельная отправка `nonce` и `image_base64` в `decide`. Результат показывается только из ответа сервера; повторные клики блокируются. После ответа кадр удаляется из состояния. При неизвестном результате не заявляется разрешение.
- `/phone`: сканер QR внутри страницы (jsQR, до 4 кадров/с, уменьшение кадра до 480 px), открытие QR штатной камерой телефона/ссылкой, сохранение ссылки в sessionStorage для возврата после входа, удаление fragment из адресной строки; есть ручной ввод ссылки. Поддерживается только origin этого приложения. Камера останавливается после распознавания, при скрытии страницы и уходе.
- Телефон создаёт неэкспортируемый приватный WebCrypto-ключ ECDSA P-256 и хранит CryptoKey в IndexedDB, раздельно по Keycloak URL/realm/sub. Сервер получает только открытый SPKI-ключ через `/devices`. Подтверждение подписывает UTF-8 nonce и шлёт base64url signature в `/scan`; формат совместим с backend ieee-p1363.
- Подтверждение телефона не трактуется как открытие смены. Ошибки API показываются по русскому reason_human/reason; HTTP 200 с confirmed=false или decision=deny не становится успехом.

## Ограничения текущей интеграции

- По явному разрешению пользователя добавлены `GET /me` и `GET /attempts/:id`. Планшет ждёт серверный статус scanned; телефон читает решение после подтверждения. Своя смена читается при входе, возвращении на экран, после результата и раз в 60 секунд. Ошибка чтения отключает отправку. Контракт: [demtory-api-needs.md](../../docs/demtory-api-needs.md).
- GPS: `getCurrentPosition`, enableHighAccuracy=false, maximumAge=60000, timeout=10000; без watchPosition, не чаще 60 секунд. При закрытой/неизвестной смене датчик не запрашивается; при скрытии страницы поздние ответы игнорируются. Перед POST /locations читается смена; shift_id проверяется сервером в транзакции. Кнопки Бетон/Котлован/Курилка явно обозначены как симуляция и используют source=button. В симуляции GPS выключен.
- WebCrypto с extractable=false запрещает экспорт через стандартный API, но не доказывает аппаратную привязку/невозможность копирования профиля браузера и не является WebAuthn. Текущий backend разрешает самостоятельную повторную регистрацию ключа по JWT; поэтому невозможность прохода за другого ещё нельзя считать доказанной. См. [W3C WebCrypto](https://www.w3.org/TR/webcrypto/). Политику замены/проверки устройства должен закрыть backend; фронт не обходит её копируемым секретом.
- При потерянном ответе decide повторная отправка блокируется; итог читается через GET /attempts/:id. Неизвестный исход не становится разрешением. Cancel и decide доступны только gate-владельцу. GET не выдаёт nonce и допускает только владельца или подтвердившего worker.
- На новом устройстве, после очистки IndexedDB или другой привязки ключ может не совпасть с зарегистрированным на сервере. Повторная привязка — явная кнопка, без автоматической замены ключа при каждом входе.
- Реальный сквозной прогон Keycloak → новый человек → ключ → QR → камера → решение ещё не выполнен. HTTPS на телефоне, IndexedDB в браузере и реальные камеры требуют проверки на стенде.

## Проверки

```sh
npm run test
npm run typecheck
npm run build
npx playwright install chromium
npm run test:e2e
```

Тесты проверяют совместимость WebCrypto-подписи с серверным форматом, отказ на изменённый nonce/другой ключ, запрет экспорта, проверку ссылки QR и обработку серверных отказов/невалидного ответа. 8 Playwright-сценариев проверяют UI, IndexedDB после перезагрузки, подпись, сканер из видеопотока, GPS/симуляцию/минутный интервал и восстановление потерянных ответов. HTTP Keycloak/API и датчики заменены в тестах. Живую проверку настоящих Keycloak, face и телефона это не заменяет. Пошаговая ручная проверка — [demtory-status.md](../../docs/demtory-status.md).

Страницы: `src/app/gate`, `src/app/phone`; общие компоненты: `src/components`; API и подпись: `src/lib`. Распределение работы — [tasks-demtory.md](../../docs/tasks-demtory.md). Realm и compose этим изменением не затрагиваются. Исключение для двух методов API и проверки shift_id согласовано пользователем.
