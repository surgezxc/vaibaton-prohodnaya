# a-shorokhov — лица и слой модели

Источник правды: [architecture.md](architecture.md), [roles.md](roles.md), [decisions.md](decisions.md), [hackathon-plan.md](hackathon-plan.md). Скиллы в `.cursor/` могут подсовывать другие модели, коды `FACE_*` и passkey. Делай как в схеме.

## Что изменилось

- Сводка помощника включает отклонения и аномалии, их считает SQL. Модель не пишет и не переставляет числа: сервер подставляет значение по имени поля (`people`, `shifts`, `deviations`, `refusals`, `anomalies`).
- Лицо и текстовую модель вызывает только один модуль API, `apps/api/src/modules/outbound.ts`. `MODEL_PROVIDER` остаётся текстовым: `gigachat` или `ollama`, локально `qwen3:4b`. YOLO и InsightFace в этот переключатель не складывай.
- [local-model.md](local-model.md) говорит ollama и `qwen3:4b`. Не документируй `qwen2.5` и не пиши переключатель `external|local`.

Не пиши UI. Не учи свою сетку. Не выдумывай цифры помощника.

## 1. Цель и Д11

Сервис лиц отличает 0 / 1 / 2+ и сравнивает кадр КПП с эталоном 1:1 (InsightFace `buffalo_l`). Слой модели — GigaChat и Ollama `qwen3:4b`, цифры только из SQL, нет строк → «данных нет».

На защите (Д11) объясняешь: почему это не «на кадре есть лицо», как считается cosine 1:1, где живое лицо, как переключается `MODEL_PROVIDER`, какие tools и почему модель не считает посещения. `decide()` и таблицы — Владислав.

## 2. Каталоги

**Твои**

- `services/face` — `count_faces`, `embed`, `compare`
- `prompts/` — шаблоны GigaChat / разбор ответа
- слой модели **по контракту** (один модуль, который вызывает API): провайдеры GigaChat и Ollama, не роуты журнала и не `decide`

**Не трогать**

- `apps/web` целиком (`/gate` `/phone` `/admin` `/manager`)
- `apps/api` модули персонала, проходов, смен, перемещений, аналитики — Владислав. Помощник в API зовёт **твой** слой, но `POST /assistant/*` вешает он, если не договоритесь иначе в чате
- `docker-compose.yml` — алисон впишет сервис `face`, когда скажешь порт и команду
- `docs/run.md`, `docs/local-model.md`, `docs/limits.md`, `docs/ai-usage.md`, `.env.example` — алисон; ты отдаёшь ей текст и имена env
- `Первый пакет/` не копировать в сервис как «единственную базу лиц»

Коммиты от своего git user.

## 3. Что реализуешь (как в схеме, без добавок)

### Face

Детект — готовый YOLO-face. Сравнение 1:1 — InsightFace `buffalo_l`. Свою модель не учим.

| Функция | Смысл |
| --- | --- |
| `count_faces` | 0 / 1 / 2+ лиц на кадре |
| `embed` | вектор эталона или кадра, только если лиц ровно 1 |
| `compare` | cosine эталон ↔ кадр КПП, один к одному, не 1:N по всей базе |

Правила из §«Проход»:

- заведение: 0 или 2+ → эталон **не сохранить**; только «1»; embedding в БД пишет API;
- на **проходе** — ещё проверка «живое лицо»;
- на **регистрации** живое лицо **не** проверяем (фото из пакета);
- чужое лицо на проходе — отказ, фразу в журнал пишет API.

Демо: `_фото` = эталон, `_проходная_*` = кадр КПП.

HTTP-пути сервиса схема не фиксирует — только три функции. Пока Влад не дал вызов из API, подними локальный процесс с этими тремя именами. Новые глаголы (`detect_and_allow`, `who_is_it`) не добавляй.

### Модель

Один слой. Адрес из `.env`. На защите меняют env.

```
MODEL_PROVIDER=gigachat|ollama
```

Локально `qwen3:4b` (рабочая, не заглушка).

Эндпоинты, которые слой обслуживает (вешает API):

- `POST /assistant/ask`
- `POST /assistant/summary`

Tools — **только агрегаты SQL**, не сырые строки журнала в промпт как «придумай»:

- кто внутри;
- отказы за период;
- кто меньше 4 часов за день;
- зона с максимумом посещений — для вопроса про посещения;
- в какой зоне больше всего людей — разные люди, в ответе «человек»;
- сводка (люди, смены, отклонения, отказы, аномалии). Числа подставляет сервер по имени поля.

Цифры считает SQL / API. Модель формулирует. Нет строк → **«данных нет»**. Таймаут GigaChat — статус и повтор, не выдуманные числа.

Помощник обязан закрыть примеры кейса:

- кто внутри;
- кто вчера < 4 часов;
- в какой зоне вчера больше всего людей — счёт разных людей, слово «человек», не «посещение»;
- отказы за неделю и почему;
- сводка периода;
- «данных нет».

Тепло, маршруты и отчёты — **посещения**. Подряд точки в одной зоне = одно посещение. Пусто = 0. Вопрос «больше всего людей» — отдельный счёт, не подменяй его посещениями. Отклонение — смена короче 4 часов. Аномалия — отказ или открытая смена без единой точки.

### Что не твоё

Таблицы: `people` (эталон embedding, `keycloak_sub`), `attempts`, `shifts`, `locations`, `zones`, `journal`, `visits` — Владислав. Ты не проектируешь схему заново.

## 4. Чеклист по порядку

### Первый час

1. Прочитай схему §«Проход», §«Помощник», §«API», решение 6.
2. Качни веса YOLO-face и InsightFace `buffalo_l`. Без весов дальше нельзя.
3. Проверь ключ GigaChat (из `.env`, не в git). Если ключа нет — скажи в чат; локальный `qwen3:4b` всё равно поднимай.
4. Скелет `services/face`: три функции, ответ на 0 / 1 / 2+ уже честный (не `if есть_лицо: 1`).
5. Скелет слоя: `getModel()` + два провайдера. Промпт-файлы в `prompts/`, не строка в коде UI.

### Клей

6. Алисон зовёт face с админки через API: заведение Гаджиева, `_фото`. 0 и 2+ не сохраняются. 1 → embedding уходит во Влада.
7. `decide` Влада вызывает `compare` эталон человека из JWT/попытки ↔ кадр КПП. Ты не выбираешь человека 1:N.
8. Подключи живое лицо только на проходе.
9. Tools помощника читают те же посещения / смены / журнал, что аналитика. Провайдер из `MODEL_PROVIDER`.

### Сломать

10. **Чужое лицо:** эталон Гаджиева + `_проходная_*` другого человека → `compare` не проходит, API отказывает.
11. Кадр без лица и кадр с двумя лицами на enroll — нельзя сохранить. На проходе — отказ, не «пропущен».
12. Свой `_фото` + свой `_проходная_*` Гаджиева — проходит порог (подбери порог на пакете, число в чат и в журнал решений через алисон).
13. Выдерни GigaChat (неверный ключ / нет сети) — статус и повтор, в ответе нет выдуманных «12 человек».
14. `MODEL_PROVIDER=ollama` — тот же вопрос, живой `qwen3:4b`, те же цифры из SQL.

### Полировка

15. Веса и модель не коммитить бинарниками, если это ломает репо; путь и команда скачивания — алисон в `docs/run.md` / `docs/local-model.md`.
16. Объясни вслух железо / скорость / цену / приватность (кейс 5.3) — черновик текста отдай алисон в `docs/limits.md`.
17. Репетиция 10–15 мин: сменить `MODEL_PROVIDER` и показать отказ 0 лиц.

## 5. Как работать, пока нет API и UI

Face без Влада:

- скрипт или HTTP на localhost: подать `_фото` Гаджиева → `count_faces=1` + `embed`;
- пустая картинка / два лица (склей два портрета) → 0 или 2+;
- `compare(embed(фото Гаджиева), embed(проходная Иванова))` vs своя проходная.

Модель без аналитики:

- tools возвращают пустой агрегат → формулировка **«данных нет»**;
- tools возвращают фикстуру `{ "inside": 0 }` только как локальная проверка SQL-формы, не как ответ судьям;
- оба провайдера: один `complete()` на один и тот же промпт из `prompts/`.

В compose сам сервис не прописывай. Алисон: имя сервиса `face`, что качать при `up`, какие переменные. Пока compose нет — `python` / uvicorn у себя.

Заглушка `return allow` / `return "на объекте 8 человек"` запрещена даже на час.

## 6. Приёмка

Отказы наружу — русский текст через API, не твои коды в UI. Из схемы обязательно:

- эталон не сохранить при 0 или 2+ лиц;
- нет строк у tools → **«данных нет»**;
- таймаут внешнего провайдера — статус и повтор, не числа с потолка.

| Сделано | Не сделано |
| --- | --- |
| `count_faces` честно даёт 0 / 1 / 2+ | «Есть лицо» = успех |
| Эталон пишется только при 1 лице | Сохранили карточку без вектора |
| `compare` 1:1 с эталоном, YOLO-face + `buffalo_l` | 1:N «кто ближе», своя обученная сеть |
| Живое лицо на проходе, на регистрации нет | Liveness на `_фото` из пакета (сломает заведение) |
| Чужой кадр КПП не проходит | Порог 0 или всегда true |
| `MODEL_PROVIDER=gigachat\|ollama`, локально `qwen3:4b` отвечает | Один провайдер или мок вместо Ollama |
| Tools только агрегаты из списка; цифры не из модели | Модель считает посещения сама |
| Пусто → «данных нет»; таймаут без фантазии | Заготовленный ответ помощника |
