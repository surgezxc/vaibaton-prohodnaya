# Отчёт об использовании ИИ-ассистентов

## Использование

В этой рабочей сессии Codex использовался для создания страниц администратора и руководителя, адаптера API, Keycloak-входа, серверного прокси и оформления интерфейса. Также подготовлены изменения Compose для подключения web при сохранении face service из актуальной ветки GitHub, а также инструкции запуска и ограничения текущей интеграции. API из `apps/api` и Keycloak realm из актуальной ветки GitHub сохранены.

## Работа команды

Требования, границы каталогов, URL API, роли, состав полей карточки и критерии достоверности данных взяты из кейса и командных документов. Архитектура и журнал решений не переписывались. Проход не решается на клиенте; экран показывает текст отказа от сервера. Пустые ответы не заменяются демонстрационными цифрами.

## Ошибки и корректировки

- В первой редакции тепловой карты использовался неподтверждённый числовой порог «мало / много». После сверки с командным планом порог удалён: сейчас нулевые и ненулевые посещения визуально различаются, а ненулевые значения сравниваются между собой.
- После обновления личного брифа Алисон калибровка плана отделена от полигонов зон: UI читает и отправляет три точки через `/plans/:id/calibration`; координаты границ и калибровки пересчитываются из позиции на изображении в пиксели плана. Регистрация ключа телефона оставлена экрану `/phone`.
- Стенд переключён на HTTPS для страниц и браузерного Keycloak; сертификат задаётся локально и исключён из Git. В `docs/run.md` добавлена установка доверенного сертификата на телефон.
- Реализация API и realm-файл присутствуют в репозитории; в этой рабочей сессии их код не запускался. HTTPS redirect URI для браузерного клиента `web` нужно сверить с адресом стенда в Keycloak.

## Проверки и ответственность

На момент составления отчёта стенд не собирался и приложения не запускались. Сквозные сценарии с API и распознаванием лиц не подтверждены. Перед сдачей участник команды должен просмотреть свой код, сверить клиент Keycloak и пройти запуск по `docs/run.md`.
