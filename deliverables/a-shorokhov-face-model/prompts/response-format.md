# Проверяемая формулировка

Модель выбирает порядок и один из двух русских вариантов каждой фразы. Каждый
вариант уже привязан к конкретному SQL-полю. Сервер принимает только JSON
`{"sentences":[{"id":"numbers.people","variant":0}, ...]}` и подставляет
значения из фактов. Все id должны присутствовать ровно один раз.

Это ограниченный язык формулировок: модель не может объявить `people=12` как
`denials=12`, подменить имя или дополнить сводку выдуманным событием. Свободный
текст, лишние поля, неизвестные id, повтор или пропуск факта отвергаются. При
неверном формате есть одна попытка повторной генерации; затем ошибка доходит
до существующего обработчика API (`unavailable`, `retry=true`, факты отдельно).
Неверный ключ, HTTP-ошибка и таймаут не запускают скрытую замену провайдера.

SQL, выбор tool, права и HTTP-маршруты остаются в API. Поддерживаются только
`who_inside`, `under_four_hours`, `busiest_zone`, `denials`, `summary`.
Метрика busiest_zone — посещения по текущему контракту команды.
