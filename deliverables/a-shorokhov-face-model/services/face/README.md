# Face — часть a-shorokhov

Контракт уже задан в основном репозитории, в `apps/api/src/face/client.ts`; здесь реализованы его три
HTTP-вызова. Человека выбирает API, embedding хранит API, проход решает `decide()`.
Сервис не хранит фотографии и не ищет человека по всей базе.

## Запуск без API

Из корня этой папки deliverable, Python 3.12:

```sh
cd services/face
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python download_models.py
.venv/bin/uvicorn app:app --host 127.0.0.1 --port 8000
```

Первое скачивание требует сети. YOLO-face берётся из опубликованного release и
проверяется SHA256; buffalo_l и RGB-liveness скачивает InsightFace. Каталог
`.models/` исключён из Git. После скачивания модели работают локально.

Во втором терминале, из `services/face`:

```sh
.venv/bin/python -m unittest -v test_face.py
.venv/bin/python smoke.py '../../../../Первый пакет'
.venv/bin/python check_package.py '../../../../Первый пакет'
```

На macOS путь может отображаться с составными Unicode-символами; используйте
автодополнение имени каталога. `smoke.py` проверяет настоящий HTTP-сервис: 0/1/2
лица, отказ enroll при 0/2, embedding 512, свой Гаджиев `_проходная_3.jpg` и чужой
Иванов `_проходная_1.png`. Это проверка сохранённых снимков, не живой камеры.

`check_package.py` проверяет весь пакет и пишет `.reports/package.json`.
Ненулевой код выхода означает обнаруженное ограничение качества, а не успешную
приёмку. Фотографии источника скрипты не меняют.

## Вызовы для Владислава

Все запросы — JSON. `image_base64` — содержимое JPEG/PNG/WebP в base64; допустим
также data URL. До 6 MB после декодирования и 16 мегапикселей. Только внутренняя
сеть API; порт face не должен публиковаться в интернете.

| POST | Тело | Ответ |
| --- | --- | --- |
| `/count_faces` | `{image_base64}` | `{count}` — фактическое число лиц YOLOv8-face |
| `/embed` | `{image_base64}` | `{embedding: number[512]}` — только при одном лице |
| `/compare` | `{embedding: number[512], image_base64}` | `{face_count, score, match, live}` |

`/embed` не запускает liveness. На проходе YOLO проверяет количество, SCRFD из
buffalo_l получает landmarks того же лица (сопоставление боксов), ArcFace из
buffalo_l даёт четыре вектора: обычный выровненный crop, зеркальный и два
варианта с CLAHE по яркости. Их сумма нормируется в 512-мерный embedding. Cosine — скалярное произведение нормированных векторов.
RGB-liveness запускается только в `/compare`. При 0/2+ возвращаются `score=null`,
`match=false`, `live=false`. `match` означает только совпадение личности; сервер
обязан дополнительно проверить `live` и свои условия попытки.

Плохой ввод/неоднозначное лицо — HTTP 422; слишком большое тело — 413; ошибка
модели — 503. API уже превращает их в отказ и запись журнала. Исключение модели
никогда не превращается в разрешение.

## Передача алисону

Dockerfile лежит здесь; build context `./services/face`, внутренний порт 8000.
Первый старт скачивает веса, поэтому нужен постоянный volume в `/models`.
В существующий Compose алисон добавляет:

```yaml
face:
  build: ./services/face
  environment:
    FACE_MODEL_ROOT: /models
    FACE_MATCH_THRESHOLD: "0.69"
    FACE_DETECT_CONFIDENCE: "0.25"
    FACE_LIVENESS_THRESHOLD: "0.8"
  volumes:
    - face_models:/models
```

И объявляет volume `face_models`. У API уже есть `FACE_SERVICE_URL=http://face:8000`.
Для работы API на хосте адрес `http://127.0.0.1:8000`; API в Docker при face на
Mac — `http://host.docker.internal:8000`, face нужно слушать доступный интерфейс.
Веса заранее скачать до репетиции; первый старт дольше `FACE_TIMEOUT_MS` API.

Env для `.env.example`: четыре FACE-переменные выше плюс API
`FACE_SERVICE_URL`, `FACE_TIMEOUT_MS` (текущий API по умолчанию 8000 ms).
Compose и общие документы здесь не изменены.

## Камера без общего стенда

Запустите диагностическую страницу вместо обычного `app:app`:

```sh
.venv/bin/uvicorn camera_app:app --host 127.0.0.1 --port 8001
```

Откройте http://127.0.0.1:8001 в Safari или Chrome и разрешите камеру.
Микрофон не запрашивается. «Включить камеру» → «Снять мой эталон» →
«Проверить новый кадр». Сначала проверьте себя прямо, с небольшим поворотом
и при другом освещении; затем другое лицо, пустой кадр, два лица и свою
фотографию на экране/бумаге. Кнопка выключения останавливает видеодорожку.
Можно загрузить файлы вместо камеры для воспроизведения ошибок.

Это самостоятельная диагностика, а не проходная с открытием смены. Эталон
живёт только в памяти страницы; сохранение в `people.embedding` выполняет
существующий `POST /people` общего API с ролью admin. На проходе API читает
эталон из БД и вызывает этот же `/compare`. Подключение контракта проверено
по исходникам API; живой PostgreSQL/Keycloak стенд здесь не запущен.

«Скачать отчёт» выгружает только время, источник camera/file, score, количество
лиц, match/live и время ответа — без фото и embedding. Отчёт сам по себе не
знает, было в кадре своё, чужое лицо или фотография: это нужно отметить при
ручной проверке. `match && live && face_count === 1` — результат проверки лица,
разрешение прохода всё равно принимает общий сервер.

Тесты поведения страницы (Node >=22, настоящую камеру не заменяют):

```sh
node --test test_camera.cjs
```

## Обновление эталонов

**Новый pipeline `buffalo_l_flip_clahe_v1` несовместим с прежними эталонами
по калибровке.** Формат HTTP остаётся прежним, но все эталоны нужно заново
получить через `/embed` из исходных регистрационных фотографий и записать
через общий API. Не смешивать старые векторы buffalo_l с новыми векторами.
После обновления камеры перезагрузить страницу и переснять эталон.

## Фактические результаты и ограничения

Проверено 10.10.2026 на Mac M4 Pro/24 GB, CPUExecutionProvider: 10 эталонов,
58 кадров проходной, из них 52 с одним лицом и 6 с двумя обнаруженными лицами.
Для 52 кадров выполнено 468 чужих сравнений. Pipeline с усреднением четырёх
представлений и порогом **0.69** даёт **41/52 своих, 0/468 чужих**. Прежний
вариант с порогом 0.74 давал 31/52 своих. Самый высокий чужой cosine нового
варианта 0.68627; минимальный свой 0.45343. Единого порога для всех своих
без чужих совпадений по-прежнему нет. Цель 45/52 не достигнута; пользователь
выбрал сохранить buffalo_l и зафиксировать честный результат.

`check_package.py` по умолчанию сохраняет цель 45, поэтому возвращает
ненулевой exit code при 41. Шесть отказов из-за двух лиц выделены отдельно,
ошибок обработки пакета нет. Варианты обработки и калибровка — в `../../reports`.
Это подбор на том же пакете, не независимый тест; запас до худшего чужого
сравнения мал. Порог нужно сообщить команде для существующего решения 6.

Сквозной прогон всех пар через работающий HTTP-сервис:

```sh
python check_package.py '../../../../Первый пакет' --http-url http://127.0.0.1:8001
```

Он сверяет реальные ответы `/compare` со всеми 52 своими и 468 чужими
cosine, а также проверяет отказы на шести кадрах с несколькими лицами.
Граница 45/52 от этого не меняется.

RGB-модель оценила сохранённые кадры как live; это не доказательство защиты
от распечатки/экрана. Проверка настоящего человека, экрана и бумаги через
камеру пока требует участия пользователя. Live camera нельзя отмечать
проверенной по файлам или мокам. Docker-сборка не проверена: daemon не запущен.
