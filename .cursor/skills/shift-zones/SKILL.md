# Смены, гео, зоны

Проход открывает/закрывает смену. Телефон шлёт точки, пока смена открыта. Зоны и привязка координат — в админке, не в репозитории константами. Картинок площадки в исходном docx нет: схема-заглушка + загрузка подложки, когда файлы выдадут.

## Когда вызывать

- «Кто сейчас внутри и с какого времени».
- Редактор зон, теплокарта, маршруты.
- Пинг гео с телефона, имитация для судей.

## Смена

- Успешный `in` → открыть `shift` (`person_id`, `opened_at`, `opened_attempt_id`).
- Успешный `out` → закрыть (`closed_at`, `closed_attempt_id`).
- Второй `in` при открытой смене → deny `ALREADY_INSIDE`.
- `out` без смены → deny `NOT_INSIDE`.
- Экран руководителя: список внутри = открытые смены, сортировка по `opened_at`.

Не считать «внутри» по последней гео, если прохода не было.

## Гео

Пока `shift` открыта, телефон периодически `POST /geo { lat, lng, at, accuracy }`.

- Интервал 10–30 с (не каждую секунду).
- Без открытой смены сервер отбрасывает (или `warn` в журнал, не рисует маршрут).
- Имитация для защиты **обязательно показать**: кнопка «демо-точка», query `?mock=1`, или букмарклет. Описать в `docs/run.md`. Реальную стройку не требуют.

Хранить точки в БД (время, person, coords). Это сырьё аналитики.

## Зоны в UI

Админ на схеме площадки:

- загрузить подложку (когда выдадут) или сетку-заглушку;
- нарисовать полигоны (не менее 2–3 зон для демо);
- имя зоны, цвет;
- сохранить в БД как GeoJSON / список вершин в тех же координатах, что и гео.

`pointInPolygon` на сервере (или при агрегации). Смена зоны точки — атрибут записи, не ручной SQL.

Менять зоны без деплоя. Координаты полигонов не хардкодить в React.

## Аналитика (12 баллов)

Одна **описанная** метрика, считать одинаково везде. Рекомендация:

**Доля человеко-времени смены в зоне** = сумма интервалов между соседними точками, попавшими в зону, / длительность смены (или выбранного окна).

Альтернатива: «сейчас в зоне N человек» — слабее для «где проводят смену», но допустима, если в доке честно.

Обязательные виды:

| Вид | Правило |
| --- | --- |
| Тепло | интенсивность по метрике, не случайный градиент |
| Пусто ≠ мало | зона без точек ≠ зона с 1 редким пингом; легенда: «нет данных» vs «низкая активность» |
| Маршруты | ломаная по точкам человека за окно |
| Фильтры | человек, зона, интервал дат/смены |

Рисовать тепло без точек в БД — дисквал («рисованная аналитика»).

## Анти-паттерны

- Зоны массивом в `zones.ts`.
- «Внутри» = последняя точка в радиусе 500 м от офиса.
- Гео как замена лица/телефона на проходе.
- Одна и та же заливка всех зон «для красоты».
- Молчать, как судье подвигать точку.

## Первое действие

Таблица `shifts` + `geo_points` + `zones` (полигон JSON). API «кто внутри» = `SELECT` открытых смен. Редактор зон — сразу в админке, даже на клетчатой подложке.
