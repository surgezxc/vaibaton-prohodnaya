# Git, документы, защита

Допуск проверяет доступность репозитория, видимую историю работы, отсутствие секретов, обязательную документацию и владение решением. Ориентир кейса — не менее 15 осмысленных коммитов на весь репозиторий; у каждого участника должен быть виден собственный вклад. Это не требование 15 коммитов от каждого и не самостоятельный числовой порог допуска.

На защите судья заводит нового человека, проверяет невозможность прохода за другого, задаёт вопросы по коду и просит небольшую правку на 10–15 минут. Не смешивай условия допуска, балльные критерии и основания снятия с конкурса.

Это скилл процесса, не генератор 15 пустых коммитов в конце.

## Когда вызывать

- Первые 20 минут дня.
- Перед каждым крупным куском (проход, телефон, зоны, модель).
- За час до защиты: чеклист Д1–Д11 и доки.

## Git с первой минуты

Следующие команды и сообщения — примеры для команды. Не создавай коммиты и не отправляй изменения без запроса пользователя. При запросе на просмотр выполняй только чтение; подготовка документации не даёт разрешения на Git-операции.

```
git init   # или этот репо
# .env в .gitignore сразу
# .env.example без ключей
```

Коммиты маленькие и по делу; пример возможной истории, а не обязательный список:

1. chore: репо, gitignore, env example  
2. feat: каркас сервера и БД  
3. feat: таблица people  
4. feat: заглушки трёх UI  
5. feat: enroll + отбраковка лица  
6. feat: создание attempt  
7. feat: phone credential  
8. feat: decide на сервере  
9. feat: журнал попыток  
10. feat: смены вход/выход  
11. feat: geo ping  
12. feat: редактор зон  
13. feat: кто внутри + метрика  
14. feat: слой модели, провайдер local  
15. feat: провайдер external  
16. feat: помощник grounded  
17. docs: run, schema, local-model, decisions  

У каждого участника есть коммиты от своего имени. Кейс не задаёт минимальное число коммитов на человека. Не подменяй авторство и не создавай искусственную историю ради количества.

Секреты: ключи, `.pem`, дампы лиц судей. При обнаружении утечки сообщи пользователю и предложи отзыв/ротацию ключей. `git rm --cached` не удаляет секрет из предыдущей истории; изменения истории и внешние действия не выполняй без соответствующего запроса.

## Документы — отдельные файлы

Не одна простыня README. Минимум:

| Файл | Содержание |
| --- | --- |
| `docs/run.md` | что за система, запуск с нуля на чистой машине, настройки, URL ролей, учётные данные для стенда, ожидаемый результат, имитация гео и камера; без настоящих секретов |
| `docs/schema.md` | схема компонентов и связей плюс пояснения: кто с кем общается, где данные и где вызывается модель; описание сущностей — дополнение |
| `docs/decisions.md` | 3–6 записей: решение, рассмотренные варианты, причина выбора и риски |
| `docs/local-model.md` | файлы запуска, настройки и проверенная пошаговая инструкция запуска и переключения на локальную модель; справочник `/model-layer` — основа, не готовая инструкция продукта |
| `docs/limits.md` | что не успели, что работает частично, ограничения имитации и планы на следующие 10 часов |
| `docs/ai-report.md` | какие части генерировали ИИ-ассистенты, что делали вручную, где ассистент ошибся и как это обнаружили; работу модели внутри продукта описывать дополнительно |

Названия файлов — соглашение набора, а не требование кейса. Проверяй содержание всех шести документов, а не только их наличие. Не выдумывай выполненные проверки, решения команды или ошибки ассистентов.

Журнал решений писать **по ходу** (после выбора библиотеки лица, после выбора метрики), не в последние 10 минут.

## Защита: сценарий

Держать открытыми три окна + этот чеклист.

1. **Д9.** Судья в админке: фото, двое в кадре — отказ; один — сохранился.  
2. **Проход.** Планшет: судья + вход. Телефон судьи подтверждает. Зелёный, причина не нужна. Внутри — он.  
3. **Д10.** Выбрать другого человека, камера судьи и/или чужой телефон → отказ, `reason_human` вслух. Внутри не появился.  
4. **Кто внутри / зона.** Показать список и схему.  
5. **Помощник.** «Сколько отказов за час?» — цифра = журнал.  
6. **Провайдер.** Сменить `MODEL_PROVIDER`, тот же вопрос.  
7. **Правка 10–15 мин.** Типовые: добавить причину в журнал, фильтр по зоне, текст отказа понятнее. Не «перепишем матч».  
8. **Любой файл.** Знать, где `decide`, где `compareFace`, где промпт.

## Анти-паттерны

- Один коммит «done» на 40 файлов.  
- README с ключом GigaChat.  
- Документация только в чате Cursor.  
- Не уметь найти `decide` за 20 секунд.

## Первое действие

При разрешённой задаче на подготовку проекта: `.gitignore` + `.env.example` + черновики `docs/decisions.md` и `docs/run.md`. Сообщить о подготовленных изменениях. Коммит `chore: repo bootstrap` — только по запросу пользователя; при проверке существующего набора ничего не создавать.
