# Вайбатон: «Проходная», 7–10 часов

Кейс — контроль прохода на стройке. Готового продукта в этом репо нет. Этот скилл — каденция и отказ от лишнего. Проход ломают судьи: решение только на сервере, лицо 1:1, нельзя пройти за другого.

Бриф: читать `docs/case-prohodnaya.md` в контексте проекта (или выданный docx). Не кейс «документы соискателей».

## Когда вызывать

- Старт дня, до каркаса.
- «Давайте натив / свою нейросеть лиц / Kafka / красивый лендинг».
- За 90 минут до защиты — жив ли проход Д9/Д10.

## Каденция

| Окно | Цель | Готово, если |
| --- | --- | --- |
| 0–20 мин | `/git-docs-defense`: репо, `.env.example`, первый коммит, заготовка журнала решений | Git с начала, секретов нет |
| 20–90 мин | Каркас: отдельный бэкенд + БД + три UI-заглушки | Три URL, таблица `people` живая |
| 1.5–4 ч | Вертикальный проход | Завести человека → вход разрешён → попытка за другого отказана, причина на планшете, запись в журнале |
| 4–6 ч | Телефон + смена + гео | Одноразовое подтверждение, координаты пока смена открыта; имитация гео задокументирована |
| 6–8 ч | Зоны в UI, «кто внутри», одна метрика аналитики | Пусто ≠ мало; зоны не в коде |
| 8–9 ч | Помощник + два провайдера модели | Цифры из БД; смена провайдера из конфига |
| 9–10 ч | Доки, 15 коммитов, `/hackathon-pitch`, репетиция Д9/Д10 | Судья может завести себя |

Параллель после каркаса: `/backend-pass` + `/gate` ∥ `/worker-phone` ∥ `/enroll-admin`. Аналитика и помощник — когда события уже пишутся.

## Demo-first (защита)

За 3–4 минуты судья должен увидеть:

1. Себя заводят (эталон лица, отбраковка «нет лица / двое»).
2. Проходит сам (планшет + телефон).
3. Не проходит за другого (Д10) — отказ сервера, человеческая причина.
4. Кто сейчас на объекте.
5. Вопрос помощнику обычным языком (ответ с цифрой из БД).
6. Переключение провайдера модели.

Колода после живого прохода, не вместо.

## Что не строить

- Нативные iOS/Android. Браузер + камера + гео.
- Свою SOTA-модель лиц. Готовый детектор/эмбеддинг, но сравнение **1:1 с эталоном выбранного человека**.
- Реальную стройку и промышленный HA.
- Клиент, который ставит `allowed: true`.
- Статичный QR/токен «на всю смену».
- Данные только в памяти процесса или `data.json` рядом с кодом.
- Выдуманные цифры помощника, рисованную теплокарту без точек.
- Документы соискателей, ATS, чат-рекрутер — кейс снят.
- Красота ради красоты, второй UI-kit, микросервисы.

GigaChat **можно** как внешний провайдер. Нельзя: один провайдер «потом локальный допишем» или модель, вшитая в UI.

## Анти-паттерны

- Сначала аналитика и слайды, проход «ночью».
- «На планшете галочка — и человек внутри».
- Рефакторинг за 40 минут до защиты.
- Коммиты пачкой в конце (снимут за git-культуру).

## Первое действие

Открыть `/git-docs-defense` и `/gate-pass-security`. Зафиксировать в чате демо: завести → пройти → отказать за другого → кто внутри. Не ставить нативный SDK.
