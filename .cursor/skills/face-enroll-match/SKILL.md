# Лицо: заведение и 1:1, не детектор

Снимают с конкурса, если проход = «на кадре есть лицо». Нужно: эталон конкретного человека и сравнение кадра на проходной **с этим эталоном**.

Своя CV-модель не требуется. Нужен рабочий детектор + эмбеддинг (face-api, mediapipe + эмбеддер, insightface, облако только если бриф/сеть позволяют). Решение «похож / нет» принимает **сервер**.

## Когда вызывать

- Админка «добавить человека», захват камеры.
- Проход: кадр с планшета.
- Спор «детектор же нашёл лицо — значит ок».

## Заведение (enroll)

Не сохранить эталон, пока проверка пригодности не прошла.

1. Один кадр (лучше 2–3, взять лучший).
2. Детектор: число лиц.
   - 0 → нельзя сохранить, `FACE_NONE`.
   - ≥2 → нельзя сохранить, `FACE_MULTIPLE`.
3. Качество: лицо достаточно крупное (например min сторона бокса ≥ 80 px), не сильный блюр, не профиль 90° если модель фронтальная.
4. Посчитать эмбеддинг, сохранить в БД вместе с `person_id` и метаданными (когда, кто завёл).
5. Фото для аудита — по желанию; для матча на проходе нужен **вектор**, не «флаг hasFace=true».

UI: русские причины «На кадре никого нет» / «В кадре несколько людей — оставьте одного».

Судья заведёт себя (Д9). Форма: ФИО, роль/участок опционально, камера, статус эталона.

## Проход (match 1:1)

Вход: `person_id` выбранного контролёром человека + кадр.

```
claimed = load_template(person_id)  // нет эталона → FACE_NOT_ENROLLED
probe = embed(frame)               // 0 лиц / 2+ → FACE_QUALITY, не allow
score = cosine(claimed, probe)
allow_face = score >= THRESHOLD
```

Это **1:1**. Не искать ближайшего среди всех сотрудников и подменять ФИО.

Порог подобрать на 3–4 людях в комнате, записать в журнал решений. Типичный старт для нормализованного cosine: подобрать эмпирически, не ставить `0`.

`FACE_NO_MATCH` — лицо есть, но не того человека. Это основной отказ Д10, если телефон всё же того же (или вместе с `MIXED_IDENTITY`).

## Что писать в попытку

- `face_score` (число)
- `face_passed` bool
- не выводить сырой эмбеддинг в UI

Confidence честный: близко к порогу → всё равно решение бинарное, но в админ-журнале видно score.

## Анти-паттерны

- `if (faces.length === 1) return allow`.
- 1:N идентификация «кто это» вместо 1:1 «это ли Иванов».
- Эталон только на клиенте / в IndexedDB планшета.
- Сохранить карточку без фото «добавим потом» и разрешить проход.
- Сравнивать JPEG хешами или пиксель-в-пиксель.
- Обязать свою обученную сеть — не успеете и не требуют.

## Чеклист Д9/Д10

- [ ] Судья не сохраняется без лица.
- [ ] Двое в кадре на enroll — отказ.
- [ ] Судья проходит сам (свой эталон + свой телефон).
- [ ] Судья в кадре, в списке выбран другой — `FACE_NO_MATCH`, человек не «внутри».

## Первое действие

Модуль `face/{enroll,match}` на сервере: `countFaces`, `embed`, `compare(claimed, probe)`. Заглушка `if hasFace` запрещена даже на час.
