# Помощник: цифры считает система

Модель не «знает стройку». Она выбирает запрос/шаблон и формулирует ответ. Числа приходят из SQL/сервиса. Нет ряда — так и сказать. Выдуманная цифра — снятие с конкурса.

Слой вызова модели — `/model-layer` (два провайдера). Этот скилл — grounding.

## Когда вызывать

- Чат руководителя «кто вчера… / сколько в зоне…».
- Сводка за смену.
- Искушение скормить модели весь журнал и попросить «посчитай».

## Контур

```
вопрос
  → классификация намерения (правила или модель)
  → tools.get*(фильтры)  // только белый список
  → { rows, numbers } из БД
  → модель: сформулируй по-русски, не добавляй чисел
  → UI: текст + те же числа отдельными чипами
```

Если tool вернул пусто: «В системе нет точек за 9 октября» — не «примерно 12 человек».

Если модель недоступна: показать **сырые числа** с плашкой «формулировка недоступна, данные из БД» и кнопку повтора. Не подставлять заглушечные проценты.

## Белый список инструментов

Хватит на демо (расширять по вопросам судей):

| Tool | Вопрос-пример | Считает |
| --- | --- | --- |
| `who_inside` | кто на объекте | открытые смены |
| `inside_since` | с какого времени Иванов | `opened_at` |
| `zone_share` | сколько времени в зоне «Склад» | метрика из `/shift-zones` |
| `failed_attempts` | сколько отказов вчера / почему | журнал |
| `person_track` | где ходил Петров | точки + зоны |

Запрещено: произвольный SQL от модели, «додумай, если таблицы пустые».

Шаблоны промптов — в репо, см. `/model-layer` `references/prompts`. Не хранить промпт только в голове.

## Промпт (смысл)

- Роль: формулировщик, не источник фактов.
- Вход: вопрос + JSON фактов.
- Правило: каждое число в ответе должно встречаться в JSON. Иначе не писать число.
- Нельзя упоминать людей, которых нет в фактах.

Проверка на бэке (дешёвая): вытащить числа из ответа регекспом, сравнить с множеством из фактов. Лишнее число → обрезать ответ и вернуть «модель добавила цифру, показываю таблицу».

## Анти-паттерны

- `chat.completions` без tools и с текстом «у нас обычно 40 человек».
- RAG по README вместо БД.
- Кэш «красивого» ответа вчерашнего демо.
- Один провайдер без локального запасного.

## Первое действие

Три tool-функции над реальной БД + эндпоинт `POST /assistant/ask`, который логирует `{ question, tool, numbers, provider }`. UI — после этого.
