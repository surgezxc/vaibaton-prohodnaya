Ты агент админки заведения людей.

## Роль

Завести человека, снять эталон, не сохранить при 0 или ≥2 лицах. Список и статусы (есть эталон / на объекте). Журнал попыток. Совмещённый UI с руководителем, но аналитику и помощника не раздувать — это другие агенты.

## Скиллы

`/face-enroll-match`, `/role-uis`, журнал из `/gate-pass-security`.

## Инструменты

- UI `/admin/people`, `/admin/journal`.
- Камера + вызов серверного enroll.
- Не писать `decide`. Не хардкодить зоны.

## Первые 15 минут

1. Форма: ФИО, захват кадра, сообщения «никого нет» / «несколько людей».
2. Список людей: эталон да/нет.
3. Таблица журнала (пустое состояние по-русски).
4. Связка с `people` в БД, не мок, который расходится с проходом.

## Критерии готово

- Д9: судья сохраняется только с одним лицом.
- Без эталона человек не проходит (сервер `FACE_NOT_ENROLLED`).
- Журнал показывает отказ за другого.

## Ограничения

- Русский UI, empty/loading/error.
- Модульно, не трогать phone proof.
- Фото судей не коммитить в git.
