# Журнал решений

Формат кейса: решение / варианты / почему / чем рискуем. 3–6 записей.

## 1. Отдельный API, не «всё в Next»

- Варианты: только Next.js Route Handlers; Next + Hono в одном процессе; `web` + `api` двумя контейнерами.
- Выбрали: Next для трёх UI, Hono-API отдельным сервисом.
- Почему: Д2 и снятие с конкурса — «решение принимает клиент». Судье проще показать процесс `api` и функцию `decide`.
- Риск: два деплоя. Снимаем docker compose на один `up`.

## 2. Postgres, не SQLite и не память

- Варианты: in-memory; JSON-файл; SQLite; Postgres.
- Выбрали: Postgres в Docker.
- Почему: «файл рядом с кодом» явно не засчитывают. Перезапуск сервера не должен терять журнал.
- Риск: чуть дольше поднять. Есть `docs/run.md`.

## 3. Подпись устройства, не QR

- Варианты: статичный QR; одноразовый QR на экране; SMS; WebAuthn; WebCrypto-ключ на телефоне.
- Выбрали: ключ WebCrypto на устройстве, подпись `attemptId+nonce`.
- Почему: QR фотографируют и пересылают — дисквал. Private key не покидает телефон, скрин бесполезен.
- Риск: потерянный браузерный storage. На защите заводим устройство заново за минуту.

## 4. Лицо 1:1 на сервере, готовой моделью

- Варианты: «детект лица» в браузере; сравнение на клиенте; свой train; серверный embedding.
- Выбрали: Python `face`-сервис, эталон и кадр сравниваются cosine на сервере. Клиент шлёт картинку.
- Почему: проверка «есть лицо» ≠ 1:1, это снятие. Обучать свою модель кейс запрещает как обязаловку.
- Риск: качество на плохих вебкамах. Порог cosine в конфиге, на защите можно подвинуть за 10 минут.

## 5. Админ и руководитель — один `/admin`

- Варианты: четыре отдельных приложения; три UI как в брифе (админ+руководитель вместе).
- Выбрали: три маршрута: `/gate`, `/phone`, `/admin` (список, эталон, журнал, карта, помощник).
- Почему: бриф разрешает объединить; меньше каркаса за те же роли.
- Риск: перегруженный экран. Вкладки: Люди / Журнал / Объект / Помощник.

## 6. Метрика зон — время в зоне

- Варианты: число точек; визиты; время пребывания.
- Выбрали: секунды в полигоне. Пусто = 0, мало = (0, порог).
- Почему: нужна одна метрика на все отчёты и на защите.
- Риск: редкий ping гео. Интервал ~10 с на демо, в доке описать.
