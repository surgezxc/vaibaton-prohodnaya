# Отчёт об использовании ИИ

## В продукте

Помощник руководителя формулирует ответ языковой моделью. Считает не она.

- Внешний провайдер — GigaChat. Живой ключ на стенде не проверялся.
- Локальный — Ollama, модель `qwen3:4b`.
- Переключатель — `MODEL_PROVIDER=gigachat|ollama`. Других значений нет.
- Цифры считает Postgres. Сервер подставляет их в текст по имени поля: `people`, `shifts`, `deviations`, `refusals`, `anomalies`. Модель имя поля не выбирает и число не двигает.
- Нет строк — фраза «данных нет». Таймаут или чужая цифра — статус и повтор, на экране остаются факты из базы.
- Проход модель не решает. `decide()` и журнал — обычный код в одной транзакции. Экран показывает текст отказа от сервера. Пустые ответы не заменяются демонстрационными цифрами.

Лицо — отдельный Python-сервис: детект YOLO-face, сравнение 1:1 InsightFace `buffalo_l`. Это не языковая модель и не значение `MODEL_PROVIDER`. README сервиса и код по умолчанию держат порог **0.69**. Compose сейчас передаёт `FACE_MATCH_THRESHOLD=0.74`. Вызывает и лицо, и текст один модуль API, `apps/api/src/modules/outbound.ts`.

Как сменить провайдера на защите — [local-model.md](local-model.md).

## При разработке

Код API, миграции и эти документы собирались с агентом Cursor. Решения из [decisions.md](decisions.md) агент не пересматривал: Keycloak без passkey, одноразовый QR с планшета (показывает `/gate`, сканирует `/phone`), посещения на теплокарте, GigaChat и Ollama `qwen3:4b`, лицо отдельным сервисом, `decide()` только на сервере, открытый ключ устройства против скопированного JWT.

Экраны администратора и руководителя Алисон собирала с Codex — исходник лежит в `alison/`. Редактор плана и зон, теплокарта, маршруты, отчёт и панель помощника перенесены оттуда в `apps/web` и переписаны под фактические ответы API. Неподтверждённый порог «мало / много» Алисон сама убрала после сверки с планом команды.

Требования, границы каталогов, URL API, роли, состав полей карточки и критерии достоверности данных взяты из кейса и командных документов. Архитектура и журнал решений не переписывались.

Агент не подставлял ключи GigaChat и не коммитил `.env`. Проверка контракта — `npm test` в `apps/api`, не ответ модели.

## Сессия, в которой появились черновики в корне

В той рабочей сессии Codex использовался для создания страниц администратора и руководителя, адаптера API, Keycloak-входа, серверного прокси и оформления интерфейса. Также подготовлены изменения Compose для подключения web при сохранении face service и инструкции запуска. API из `apps/api` и realm Keycloak в репозитории сохранены. Прокси `/api/proxy` относится к копии `alison/apps/web`. Стенд `apps/web` ходит в API по `NEXT_PUBLIC_API_URL`.

Что в той сессии поправили:

- В первой редакции тепловой карты использовался неподтверждённый числовой порог «мало / много». После сверки с командным планом порог удалён: сейчас нулевые и ненулевые посещения визуально различаются, а ненулевые значения сравниваются между собой.
- Калибровка плана отделена от полигонов зон: UI читает и отправляет три точки через `/plans/:id/calibration`; координаты границ и калибровки пересчитываются из позиции на изображении в пиксели плана. Регистрация ключа телефона оставлена экрану `/phone`.
- Для камеры и геолокации нужен HTTPS. Сертификат задаётся локально и в git не коммитится (`*.pem` в `.gitignore`). Пример подъёма — в [run.md](run.md). Заход с реального телефона не подтверждён.

В `apps/web` редактор зон — маршрут `/admin/zones`. Отдельной вкладки «Зоны и схема» на стендовом `/admin` нет: она осталась в `alison/apps/web`. Утверждение черновика, что маршрута `/admin/zones` нет, к стенду не относится.

10 октября 2026 года в той среде `docker compose config --quiet` прошёл. `docker compose up --build` и переходы в браузере не состоялись: демон Docker не ответил. Фильтры, теплокарта, маршруты, помощник, сохранение плана и зон, локальная модель, сквозной face и HTTPS с телефона этой проверкой не подтверждены. Живой ключ GigaChat не подтверждался.
