# GPS и симуляция: проверка через интерфейс

## Быстрое демо без телефона

1. Открыть `/manager`, войти `manager / dev-only`. Из `/admin` сюда ведёт ссылка «Местоположение рабочих, GPS и демо зон»; роль admin тоже имеет доступ к данным.
2. В первом блоке «Местоположение рабочих» нажать «Попробовать демо».
3. По очереди нажать «Демо: Бетон», «Демо: Котлован», «Демо: Курилка».
4. Метка вымышленного рабочего перемещается по условной схеме; карточка оказывается в выбранной зоне, последние отметки показывают порядок нажатий. «Сбросить демо» очищает локальную историю.
5. Вернуться в «Реальные смены». Демо не создаёт человека, смену или координаты в БД. Аналитика ниже по-прежнему показывает серверные данные.

## Настоящий телефон и сервер

1. Зарегистрировать человека с собственным фото в `/admin`, связать с учёткой worker.
2. На `/phone` войти worker и привязать браузер. Выполнить вход через `/gate`: свежий QR → подтверждение на телефоне → лицо → разрешение сервера.
3. При открытой смене разрешить GPS и держать `/phone` видимой. В блоке «Местоположение» появятся «Сервер принял местоположение», координаты, время и точность. Следующие отправки выполняются примерно раз в 60 секунд. В фоне отправка прекращается.
4. На `/manager` открыть «Реальные смены». Данные автоматически читаются раз в минуту при видимой странице; кнопка «Обновить местоположения» позволяет увидеть запись сразу. Выключить автообновление можно флажком.
5. Для проверки зон без GPS включить на телефоне «Симуляцию зон», затем нажимать три зоны. Эти записи сохраняются на сервере с `source=button`. На странице руководителя они подписаны «Симуляция с телефона». Демо на странице руководителя и симуляция телефона — разные режимы.
6. Нажать карточку человека для отображения его метки и шести последних отметок текущей смены. Записи предыдущих смен исключаются. Отметки старше двух минут подписаны «Устарело»; ошибка чтения показывается явно, прежняя схема не выдаётся за обновлённую.
7. Выполнить выход через КПП и обновить местоположения: человек исчезает из списка открытых смен.

## Границы реализации

- Новая схема условная, без масштаба: показывает зоны, не точные позиции внутри них. Пунктир обозначает последовательность зон, а не восстановленный GPS-трек. Координаты GPS выводятся в истории.
- GPS попадает в зону после настройки плана по трём опорным точкам и границ зон в `/admin/zones`. Иначе запись окажется в «Зона не определена».
- Тепловая карта настоящего плана остаётся ниже в аналитике; для её обновления нажать «Применить». Изображение плана пока хранится в браузере, где его загрузили.
- Проверены TypeScript, существующие 12 браузерных сценариев и новые проверки автообновления/закрытия смены/ошибки сети/локального демо. Мобильная ширина 390 px проверена без горизонтального скролла. API и датчики в этих тестах подменены; физический прогон GPS не подтверждён.

- На живом HTTPS-стенде дополнительно проверены настоящий вход manager, чтение серверных данных и все три кнопки локального демо. Записи координат этой проверкой не создавались.
