# Demtory / Денис: состояние и ручная проверка

Обновлено 10.10.2026. Код `/gate` и `/phone` реализован. Минимальное API добавлено с явного разрешения пользователя; [контракт](demtory-api-needs.md). Изменения подготовлены к отправке по запросу пользователя. После слияния сохранены экраны кадров/руководителя и их общий API-клиент; клиент проходной и телефона находится в src/lib/pass-api.ts.

## Реализовано

| Задача | Результат |
| --- | --- |
| Вход и роли | Keycloak PKCE S256; gate/worker; действия без роли отключены, API проверяет JWT независимо |
| QR контролёра | Вход/выход, серверная новая попытка, одноразовая ссылка, срок из API, отмена, замена старой попытки |
| Подтверждение | Камера-сканер jsQR и ручной ввод; ECDSA P-256; неэкспортируемый приватный ключ в IndexedDB по учётке |
| Кадр КПП | Камера или JPEG/PNG-файл; доступ после серверного scanned; отдельный decide; крупный статус и русская причина |
| Потеря ответа | Восстановление результата GET /attempts/:id; повтор decide при неизвестном результате заблокирован |
| Своя смена | GET /me; состояние после входа/выхода, перезагрузки и возврата на экран |
| Геолокация | Раз в 60 с, enableHighAccuracy=false, без watchPosition; только видимая страница и известная открытая смена |
| Поздние координаты | Поздний ответ датчика после скрытия/смены режима игнорируется; shift_id проверяется API под блокировкой |
| Симуляция | Бетон / Котлован / Курилка, явно «Симуляция», source=button; GPS в этом режиме остановлен |
| Нет связи/камеры | Русская ошибка, неизвестный итог не становится разрешением; можно загрузить файл |

## Что проверено

Живой стенд и попытка проверки с Android 10.10.2026: [отдельный протокол](demtory-live-check.md). Настоящие Keycloak/API и face уже проверены; четыре пункта на физических устройствах пока не завершены.

- Web: 7 Node-тестов — подпись совместима с Node/backend, изменённый nonce и другой ключ не проходят, приватный ключ не экспортируется, QR распознаётся из кадра, ошибки API не становятся успехом.
- API: 17 тестов прошли на отдельном временном PostgreSQL на порту 55432. Проверены вход/выход, собственная смена, права чтения попытки, запрет чужому gate отменять/решать, старый shift_id, replay/TTL/чужое устройство, отказы лица и запись журнала. Face в этих тестах — управляемый тестовый HTTP-сервис; JWT — тестовый HMAC.
- TypeScript web и production-сборки web/API прошли.
- Все 8 браузерных сценариев прошли: QR/подтверждение/кадр/отказ/отмена, ключ в IndexedDB, GPS и симуляция, поздний GPS, роль, сканер из видеопотока, интервал 60 секунд, потерянные scan/decide. Проверена ширина телефона 390 px без горизонтального скролла.
- Браузерные проверки используют настоящий Next.js, Keycloak JS, WebCrypto, IndexedDB и Chromium; HTTP Keycloak/API и датчики заменены только в тестах. Это проверка поведения интерфейса, а не качества распознавания лица.

## Как проверить лично

1. Поднять стенд по [run.md](run.md): `LAN_IP` в `.env`, затем `docker compose up --build`. Телефон и ноутбук открывают `https://<LAN-IP>:8443`. В `/admin` нажать «Подставить учётку worker», приложить фото и «Завести и записать эталон».
2. В `apps/web` выполнить `npm ci`. Только если `.env.local` ещё нет, скопировать `.env.example`; проверить публичные адреса API/Keycloak. Для локальной проверки PKCE запустить `npm run dev -- --port 3002`: этот порт уже разрешён в realm. Общий compose-стенд использует 43123; для PKCE на нём владелец realm должен добавить localhost/127.0.0.1:43123 в redirectUris клиента web.
3. На компьютере открыть `http://localhost:3002/gate`, войти контролёром. В отдельном профиле браузера открыть `/phone`, войти рабочим и нажать «Привязать этот телефон» один раз.
4. На gate выбрать «Вход на объект» и открыть QR. На phone включить сканер и прочитать QR. Запасной вариант: раскрыть ручной ввод и вставить ссылку из QR. После «Подтвердить попытку» планшет должен разрешить камеру/загрузку файла.
5. Снять лицо либо загрузить файл `_проходная_*` из пакета. Нажать «Отправить кадр на проверку». При allow телефон покажет открытую смену; разрешить геолокацию. В Network проверить POST /locations: source=gps, shift_id, lat, lng, без person_id. Следующая запись не раньше чем через минуту.
6. Включить «Симуляцию»; нажать Бетон, Котлован, Курилка. В Network — source=button, zone_name и shift_id; новых GPS-записей в этом режиме нет.
7. На gate выбрать выход и повторить QR → scan → кадр → decide. При allow /me возвращает shift=null; кнопки зон отключены, GPS больше не собирается. Сервер отклоняет координаты закрытой смены.
8. Проверить отказы: чужой кадр, повторный вход, старый QR после закрытия/замены, повтор decide, worker с другим ключом. Должен быть русский отказ; смена не должна открыться. Проверить запись в журнале через роль gate/admin.
9. Во время ожидания GPS свернуть phone/заблокировать телефон: новых запросов датчика/отправок нет. При возврате сначала читается /me. Выключить сеть: разрешение прохода не появляется, повтор неизвестного decide заблокирован. При возврате сети итог читается с API.
10. Настоящий телефон открывает `https://<LAN-IP>:8443/phone` после установки ЦС, как в [run.md](run.md). Камера, GPS, считывание QR за ~25 с и три кнопки симуляции после открытой смены этим абзацем не отмечены как пройденные: их нажимает человек. Скрытие вкладки `/gate` попытку не отменяет.

## Что ещё требует стенда и команды

- Живой прогон с настоящими Keycloak, face-моделью, новым человеком и материалами пакета; тестовый face не доказывает 1:1 и liveness.
- Проверка камеры, разрешений гео, точности GPS, IndexedDB и блокировки на настоящих Android/iOS по HTTPS. Веб-страница не обещает отправку в фоне.
- WebCrypto extractable=false не доказывает аппаратную привязку телефона. API /devices пока разрешает замену ключа по JWT; строгая политика смены устройства остаётся вопросом backend. Скопированный JWT без зарегистрированного ключа отклоняется, но аппаратную защиту копирования браузерного профиля не заявляем.
- Репетиция защиты и скриншоты живого стенда с отказом «чужое лицо» — после подключения настоящего face. Самостоятельно отправлять сообщения/скриншоты команде агент не уполномочен.
