# Зависимость интерфейсов Дениса от backend

Реализовано 10.10.2026 по явному разрешению пользователя: «Да, добавь минимальное API и закончи интеграцию». Ниже действующий контракт. Планшет и телефон читают состояние попытки напрямую; журнал рабочего не открывается.

## Минимальное дополнение

`GET /me`, JWT worker. Человек определяется только по `sub`. Ответ:

```json
{
  "person": { "id": "uuid", "full_name": "ФИО" },
  "shift": { "shift_id": "uuid", "started_at": "UTC ISO 8601" }
}
```

`shift=null` означает закрытую смену. Если человек не связан — 422 с русским reason_human, не фиктивный рабочий. Ошибка чтения не считается закрытой или открытой сменой. Этот маршрут нужен для перезагрузки телефона, включения/остановки гео и проверки перед кнопкой зоны.

`GET /attempts/:id`, JWT gate-владелец или worker, который уже подтвердил эту попытку. До scan worker не читает чужие попытки. Ответ:

```json
{
  "attempt_id": "uuid",
  "status": "scanned",
  "direction": "in",
  "expires_at": "UTC ISO 8601",
  "decision": null,
  "reason_human": null
}
```

Статусы из существующей БД: pending/scanned/cancelled/decided; истечение проверяется сервером и отражается как expired без разрешения. При decided decision=allow|deny; nonce, ключи и чужие данные не выдаются. Нужен телефону после успешного scan, в том числе после потери ответа; gate может использовать для точного состояния вместо чтения хвоста журнала.

`POST /locations` принимает необязательное поле `shift_id`. Телефон передаёт его всегда. API сверяет его с открытой сменой данного sub под блокировкой строки: несовпадение — 422 «Смена изменилась. Обновите состояние телефона.», неверный UUID — 400. Без поля сохраняется прежнее поведение API. Позднее наблюдение старой смены не попадает в новую.

`POST /attempts/:id/cancel` и `/decide` также проверяют gate_sub: чужому контролёру — 404, без изменения попытки. GET-маршруты возвращают Cache-Control: no-store.

## Почему фронт не обходит зависимость

- Scan подтверждает устройство, не открывает смену.
- Табличка «смена открыта» и гео без серверного чтения были бы догадкой.
- GET /site/now и /journal не доступны worker; токен контролёра на телефон не переносится.
- Проверять открытую смену пробной записью координат нельзя: это меняет данные.
- Для роли Дениса в [tasks-demtory.md](tasks-demtory.md) явно указано «Не пиши сервер. Не придумывай новые маршруты». Пользователь явно разрешил исключение для этих минимальных изменений; остальные серверные задачи остаются у Владислава.
