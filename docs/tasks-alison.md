## Что изменилось

- Админ сохраняет, читает и правит три точки привязки на план (пиксель x/y и lat/lon) отдельно от полигонов зон. Сервер сам кладёт GPS на чертёж. Вызовы: `GET /plans`, `GET /plans/:id/calibration`, `PUT /plans/:id/calibration`. UI этих точек ещё не собран — это твоё.
- Теплокарта остаётся на посещениях. Подпись «больше всего людей» считает разных людей и говорит «человек».
- В инструкции стенда HTTPS обязателен. Гео — только пока `/phone` на экране. См. [limits.md](limits.md).
- Четыре файла Д8 уже набросаны: [run.md](run.md), [local-model.md](local-model.md), [limits.md](limits.md), [ai-usage.md](ai-usage.md). После этого коммита они всё ещё твои: проверь и держи их правдой.

Не пиши `decide()`. Не рисуй тепло без данных API.

## 3. Экраны, вызовы, поля

Роли Keycloak: `/admin` → `admin`, `/manager` → `manager`. Личность из JWT. Два разных UI, не склеивать (решение 3).

### `/admin` — кадры, ПК

Завести/править человека, эталон с отбраковкой 0/2+ лиц, список и статус, журнал всех попыток. Админ в UI рисует полигоны зон и три точки плана (пиксель x/y и lat/lon). Не в коде. Открытый ключ телефона регистрирует сам `/phone`, не админка.

| Действие | Куда |
| --- | --- |
| Заведение, эталон | `POST /people` |
| Правка | `PATCH /people/:id` |
| Список и статус | `GET /people` |
| Связь человека с учёткой | поле `people.keycloak_sub` (через заведение/правку, не id из тела на проходе). Ключ устройства шлёт телефон |
| Полигон зоны | `PUT /zones/:id/polygon` |
| Три точки плана (pixel x/y + lat/lon) | `GET /plans`, `GET /plans/:id/calibration`, `PUT /plans/:id/calibration` |
| Журнал всех попыток | `GET /journal` |

Эталон: в face 0 / 1 / 2+ лиц. Сохранить только «1». Embedding считает face, в БД кладёт API. Liveness на этом фото нет.

Поля пропуска — из пакета, не выдумывать лишние. С бейджа Гаджиева (уже выписано в плане):

- система/серия бейджа: СтройГрад-Тест
- пропуск № 314
- должность: арматурщик
- подрядчик: ООО «МонолитПодряд»
- объект: ЖК Северный
- действует до: 31.12.2027
- ФИО: Гаджиев Магомед Ибрагимович

Имена JSON полей согласует Влад под `POST /people`. В форме — эти смыслы. Статус человека — из `GET /people`.

Три зоны из пакета (имена кнопок/зон уже зафиксированы):

| Зона | Папка / кадр |
| --- | --- |
| Бетон | `Объект/Бетономешалка` — CAM-02A БЕТОН |
| Котлован | `Объект/Котлован` — CAM-05B КОТЛОВАН |
| Курилка | `Объект/Место для курения` — CAM-04A КУРИЛКА |

Схема — чертёж объекта, собранный из трёх фото пакета (выбор команды 10.10: границы рисуются в админке). Полигоны не хардкодить в репозитории.

Учётки, которые админ связывает: `worker` / `gate` / `admin` / `manager`.

### `/manager` — руководитель, ПК

Кто внутри и с какого времени; схема с нарисованными зонами; тепло посещений; пусто ≠ мало; маршруты с подписями; фильтры; отчёт по смене и по человеку; помощник.

| Действие | Куда |
| --- | --- |
| Кто внутри и с какого времени | `GET /site/now` |
| Тепло | `GET /analytics/heat` |
| Маршруты | `GET /analytics/routes` |
| Отчёты | `GET /analytics/reports` |
| Вопрос | `POST /assistant/ask` |
| Сводка | `POST /assistant/summary` |

На объекте = смена с пустым `ended_at`. Не считай «внутри» по последней гео.

Фильтры на тепло и на маршруты (как в §4.1 / схеме): **день**, **диапазон дней**, **часы внутри дня**, **люди** (один / несколько / все).

Тепло, маршруты и отчёты: **посещения**. Подряд идущие точки в одной зоне = одно посещение. Смена зоны = новое. Пусто = 0 посещений. Мало ≠ пусто. Порог «мало/много» в плане ещё открыт — визуально отличи пусто от «есть хоть одно», число порога не выдумывай. Вопрос помощника «больше всего людей» — другие люди и слово «человек», не посещение.

Маршрут: последовательность зон по времени, разные люди разным цветом, подпись ФИО.

Отчёт по смене и по человеку за период — те же посещения.

Помощник: живые данные. Нет данных → «данных нет». Нарисованные цифры — снятие блока.

## 5. Как работать, пока нет API и face

Compose: postgres и keycloak можно поднять сегодня. API/web/face — заглушки healthcheck, чтобы `up` не врал «готово».

Админ: мок `POST /people` / `GET /people` / `GET /journal`. Отказ 0 и 2+ — по-русски. Не пиши «сохранён» если face ещё не звал.

Руководитель: мок `GET /site/now` = пустой список («никого нет»), не три выдуманных ФИО. Тепло без точек API не раскрашивать.

Помощник: кнопка есть, ответ «не готово» или «данных нет», пока Влад+Шорохов не дали слой. Не подставляй заготовленные цифры.

Сиды: папка Гаджиева в `Первый пакет/Персонал/Гаджиев Магомед Ибрагимович/` — эталон `_фото`, кадры КПП не клади как эталон.

Порт web/api/face и переменные — ты хозяин compose. Денис и Шорохов пишут «нужен порт X», ты вписываешь.

## 6. Приёмка

Отказы — русский текст, не код. Фразы из схемы:

- эталон: отказ если 0 или 2+ лиц;
- помощник: **«данных нет»**;
- заглушка API: **«не готово»** — показать как есть, не заменить «ок».

| Сделано | Не сделано |
| --- | --- |
| `docker compose up` по `docs/run.md` поднимает web, api, postgres, keycloak, face | Стенд «у меня в голове», секреты в git |
| `/admin`: заведение+эталон, список/статус, журнал, рисунок зон и 3 точки | Зоны массивом в коде; эталон без проверки 0/2+ |
| Гаджиев заведён из пакета; судью тоже можно завести | Работает только на десяти людях пакета |
| `/manager`: кто внутри, тепло посещений, пусто≠мало, маршруты с ФИО, фильтры день/диапазон/часы/люди, отчёты, помощник | Рисованная аналитика; «внутри» по гео без смены |
| Админ и руководитель — разные URL | Один экран на обе роли |
| Шесть файлов 5.5 на месте и по ним можно повторить запуск и смену модели | Пустые заголовки; седьмое решение в decisions |
| Перезапуск не стирает людей и журнал | Данные в памяти процесса |
